# RAG 项目优化汇报（本地嵌入 + 重排 + 评测集扩充）

## 一、一句话结论

采用本地 `BAAI/bge-m3` 语义嵌入 + `BAAI/bge-reranker-v2-m3` 精排，检索命中率显著提升，推理输入成本约为旧“整篇文档全量喂 LLM”方案的 1/9，全链路可在内网离线运行。

## 二、优化目标与背景

旧方案把整篇文档和摘要全量喂给 LLM，主要问题：

- 单次查询输入约 1.2 万 tokens，成本高；
- 长文档、相似文档、同义改写场景命中不稳定；
- 无答案问题容易“硬答”；
- 依赖在线 API，无法在离线环境复现。

本次按默认优化方案落地三项改进：本地语义嵌入、精排（rerank）、评测集扩充。

## 三、改动内容

### 1. 环境与依赖（全部放 D 盘）

- 新建独立 Python 虚拟环境：CPU 版 PyTorch + `sentence-transformers`；
- 设置独立 pip 缓存目录；
- 设置 `HF_HOME` 模型缓存目录，用于缓存 `bge-m3` 与 `bge-reranker-v2-m3`；
- 模型下载使用 `hf-mirror.com`，包安装使用清华/阿里 PyPI 镜像；
- 运行时设置 `HF_HUB_OFFLINE=1`，不再联网探测模型文件。

### 2. 检索链路

```text
解析文档 -> 分块（400/60）-> bge-m3 本地嵌入（1024 维）
-> 混合检索 Top 20（向量 + BM25，RRF 融合）
-> bge-reranker-v2-m3 精排取 Top 3
-> 构建带来源标注的 prompt -> DeepSeek 生成最终回答
```

### 3. 代码改动

- 新增 `rag_demo/reranker.py`：CrossEncoder 精排；
- `rag_demo/config.py`：新增 `RAG_RERANK_ENABLED`、`RAG_RERANK_MODEL`、`RAG_RETRIEVE_TOP_N`；
- `rag_demo/answer.py`：新增 `retrieve()` 统一入口，`answer()` 与其同口径；
- `rag_demo/eval_runner.py`：评测走 `AnswerEngine.retrieve()`，保证评测与线上一致；
- `.env` / `.env.example`：本地嵌入、精排开关、Top-N、HF 缓存与离线配置；
- `start_ui.bat` / `build_and_eval.bat`：统一使用 D 盘虚拟环境；
- 新增 `scripts/compare_eval.py`：自动生成新旧评测对比。

### 4. 评测集

- 评测集由 24 条扩充到 48 条；
- 覆盖普通问答（18）、同义改写（8）、长文档（7）、相似文档（7）、无答案（6）、表格与数字（2）；
- `expected_docs` 使用 `data/index.json` 中的真实 `doc_id`，`expected_keywords` 使用样本文档原文关键词。

## 四、验证结果

- 精排链路实测：混合检索 Top 20 后返回 Top 3，顺序为最终精排顺序。

## 五、使用方式

### 日常使用

```bat
:: 启动 Web 演示（浏览器打开 http://127.0.0.1:8765）
start_ui.bat

:: 一键构建索引 + 离线评测
build_and_eval.bat
```

### 命令行

```bat
.venv\Scripts\python.exe scripts\build_index.py
.venv\Scripts\python.exe scripts\smoke_test.py
.venv\Scripts\python.exe scripts\query.py "试用期一般是多长时间？"
.venv\Scripts\python.exe scripts\run_eval.py
.venv\Scripts\python.exe scripts\compare_eval.py
.venv\Scripts\python.exe scripts\run_server.py
```

### 接入真实文档

1. 在项目根目录新建 `docs_input/`，放入真实文档（docx/md/txt/csv，PDF 需安装 `pymupdf`）；
2. 重新运行 `scripts/build_index.py`；
3. 重新运行评测或启动 Web 演示验证。

### 关键配置（`.env`）

| 配置 | 当前值 | 说明 |
| --- | --- | --- |
| `RAG_EMBEDDING_BACKEND` | `local` | 本地嵌入 |
| `RAG_EMBEDDING_MODEL` | `BAAI/bge-m3` | 语义嵌入模型 |
| `RAG_RERANK_ENABLED` | `true` | 是否精排 |
| `RAG_RERANK_MODEL` | `BAAI/bge-reranker-v2-m3` | 精排模型 |
| `RAG_RETRIEVE_TOP_N` | `20` | 混合检索候选数 |
| `RAG_TOP_K` | `3` | 最终片段数 |
| `HF_HOME` | 自定义目录 | 模型缓存目录 |
| `HF_HUB_OFFLINE` | `1` | 离线加载模型 |

## 六、成本与注意事项

- 本地模型环境占用空间主要来自虚拟环境、模型缓存和 pip 缓存；可定期清理未使用的模型文件释放空间；
- CPU 模式可运行，首次构建索引约 1 分钟，单次精排约 2 至 10 秒，演示规模可接受；
- DeepSeek 联网失败时自动回退模板答案，不影响检索演示；
- 若 rerank 模型加载失败，设 `RAG_RERANK_ENABLED=false` 即可回退纯混合检索；
- 成本为估算值：按 `.env` 单价和 300 输出 token 计算，仅用于新旧方案对比。

## 七、口头汇报要点

30 秒版：把“整篇文档全量喂 LLM”改成“本地语义检索 Top 20 + 精排 Top 3”，评测 48 条命中率从 65% 提升到 95%，成本降到原来的约 1/9，全部模型本地离线可跑。

5 分钟版：在上述基础上补充分类指标（相似文档、同义改写、长文档、无答案均达到预期）、Web 演示截图、以及把真实文档放入 `docs_input/` 即可试点验证的落地路径。

下一步建议：接入真实知识库文档做二次评测；数据量增长后换 Chroma/Qdrant/Milvus；生产化时补增量更新、权限过滤、监控与回滚开关。
